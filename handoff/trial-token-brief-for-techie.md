# Бриф технарю — TRY-токены для тест-драйва (@AITeamVIPBot)

## Задача

Бот `@AITeamVIPBot` должен выдавать **бесплатные TRY-токены** для
тест-драйв установщика (`openclaw-test-drive`). Это новый тариф `TRY`
рядом с существующими `VIP / STD / SUB / HRM`.

Цель: тест-драйв бесплатный, но **только по токену** — так каждый, кто
ставит демо, проходит через бота (= лид + контроль).

## Хорошая новость: ключ и механизм — те же

TRY использует **тот же Ed25519-ключ**, что VIP/STD/SUB/HRM. Менять
ключи и публичный ключ в установщике НЕ нужно. Отличие только в payload
(новый префикс `TRY`).

## Формат токена

```
TRY-<hash16>-<tg_id>-<подпись_b64url>
```

- `hash16` — 16 символов `[A-F0-9]` (UPPERCASE hex). Для платных тарифов
  это хэш email оплаты. Для бесплатного TRY оплаты нет — бери любой
  16-hex идентификатор (например, `crypto.randomBytes(8).hex().toUpperCase()`
  или первые 16 hex от `sha256(tg_id + соль)`). Это просто opaque-id для
  логов; безопасность даёт подпись.
- `tg_id` — Telegram user_id того, кто просит токен (5–15 цифр). Бот его
  и так знает из апдейта.
- `подпись_b64url` — Ed25519-подпись (base64url **без padding**, ~86 симв).

## Что подписывать

Payload (UTF-8, ровно так, с разделителем `|`):

```
TRY|<hash16>|<tg_id>
```

Подпись тем же приватным ключом, что для остальных тарифов.

## Код выдачи (Node, как для других тарифов)

```js
const crypto = require('crypto');

function makeTryToken(tgId, privateKeyPem) {
  const hash16 = crypto.randomBytes(8).toString('hex').toUpperCase(); // 16 hex
  const payload = `TRY|${hash16}|${tgId}`;
  const sig = crypto.sign(
    null,
    Buffer.from(payload, 'utf8'),
    crypto.createPrivateKey(privateKeyPem)
  );
  return `TRY-${hash16}-${tgId}-${sig.toString('base64url')}`;
}
```

Установщик проверяет это так (для справки, менять не нужно):

```js
crypto.verify(null, Buffer.from(`TRY|${hash16}|${tgId}`), PUBLIC_KEY,
              Buffer.from(sigB64, 'base64url'));
```

## Триггер в боте

Добавь команду/кнопку, например `/trial` или «🚀 Попробовать бесплатно»:

1. Берём `tg_id` из апдейта.
2. `token = makeTryToken(tg_id, PRIVATE_KEY_PEM)`.
3. (Опц.) пишем в БД: `tg_id`, `hash16`, дата, источник — для аналитики
   бесплатных лидов отдельно от платных.
4. Отвечаем пользователю готовой командой:

```
Твой бесплатный доступ к тест-драйву AI TEAM 2.0 👇

macOS / Linux — вставь в Терминал:

bash <(curl -fsSL https://raw.githubusercontent.com/tonytrue92-beep/openclaw-test-drive/main/scripts/install-trial.sh) --token TRY-XXXX...
```

(подставь реальный токен вместо `TRY-XXXX...`).

## Проверки/нюансы

- **Длина подписи:** Ed25519 = 64 байта → base64url без padding = 86
  символов. Установщик принимает 80–100 — ок.
- **hash16 строго UPPERCASE hex** и ровно 16 символов, иначе формат-гейт
  не примет.
- **tg_id — те же 5–15 цифр**, что у реального аккаунта клиента: в токен
  зашит TG ID, установщик ставит на него `allowFrom` (бот ответит только
  ему). Это анти-шаринг «бесплатно».
- Сеть для проверки токена установщику НЕ нужна (проверка локальная
  публичным ключом). Бот может лежать — уже выданные токены работают.
- **Отзыв:** так как проверка локальная, мгновенного отзыва нет (как и у
  платных). Если нужен — отдельная история (revocation-list endpoint).

## Лимиты (на твоё усмотрение)

Можно ограничить: 1 активный TRY-токен на `tg_id`, или rate-limit
(N токенов в день), чтобы не штамповали. Не блокер для запуска.
